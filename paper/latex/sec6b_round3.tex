\section{Round 3: Expanded Benchmark and Graph Ablation}
\label{sec:round3}

Rounds 0--2 --- Round~0 (Section~\ref{sec:round0}), the P0 round
(Round~1, Section~\ref{sec:p0}), and the rank-fusion round (Round~2,
Section~\ref{sec:fusion}) --- were all read on the same 100 questions,
and the Round~2 repairs were developed on exactly those questions:
every regression trace of Section~\ref{sec:fusion} was a trace of a
benchmark question.
Section~\ref{sec:p0} had argued that this yardstick reads only the head;
Round~2 added the complementary risk that its readings are in-sample. Round~3 (September 2026) therefore re-evaluates the deployed
system end to end on the 500-question benchmark of
Section~\ref{sec:benchmark}, whose 400 new questions were written after
the Round~2 repairs, with the repaired instruments of
Section~\ref{sec:evalmetrics}, and --- for the first time --- with the
knowledge graph switched off while everything else is held fixed.
Round~3 is the paper's last round on the legacy Neo4j system; graph
retrieval on the rebuilt system is reported in
Section~\ref{sec:rebuiltgraph}.

\subsection{Setup}

Three configurations ran on one deployment and one code version
(September 28--30, 2026), differing only in request-level switches
(Section~\ref{sec:pipeline}):

\begin{itemize}
\item \textbf{Graph} --- the full system of Section~\ref{sec:retrieval}
(rank fusion, $\alpha=0.3$).
\item \textbf{No-graph} --- identical signal routing, SQL strategies,
book anchors, semantic (dense) search, reranking, fusion, and pins, but
\code{use\_graph=false} gates every Neo4j-backed strategy: the typed
graph traversals, cross-reference retrieval and expansion, entity paths,
and the entity query.
\item \textbf{Semantic-only} --- the Round~0 baseline: no routing, dense
retrieval (top-20) and reranking only.
\end{itemize}

All three use Gemma~4 E4B as answer model (temperature 0.1), top-5
context, and Gemma~4 26B as judge, one run per configuration. Round~3
was not pre-registered: no primary metric, decision rule, or test family
was fixed in advance, so all of its contrasts are exploratory. Four
changes separate this deployment from Round~2. None of them changes the
graph's content (a July~8 maintenance step only attached provenance tags
to 106 existing manual edges and synchronized two manual event nodes
into the other stores), although change (ii) changes which graph
strategies run.

(i)~\code{book\_anchor} now retrieves per named book and suppresses
same-book decoys (one anchor per book in the fused list; pins only for
named books absent from the top-5); the earlier single OR-filtered
search had let one book take all ten seeds. Unlike the Round~2 graph
repairs, this fix was developed after a first evaluation of the 500
questions (July 12--14) and A/B-checked on them, so routing-side
contrasts on the expansion set are not strictly out-of-sample.

(ii)~The intent classifier was repaired. Gemma~4 E4B is a reasoning
model whose hidden reasoning tokens exhausted the classifier's 256-token
output budget; the empty reply failed JSON parsing, and the classifier
silently fell back to \code{intent=topic} with empty entity and keyword
lists. Replaying the signal detector with an empty classifier output
reproduces the logged route of every question in every Gemma graph-mode
run of Rounds~0--2 (100/100 in each 100-question run, 500/500 in a
July~15 run on the expanded benchmark). Those rounds were therefore
routed by the regex and dictionary signals alone, and strategies fed
only by classifier output never ran: R5's entity traversal was invoked
0 times in the July~15 run and 73 times in Round~3. (The Claude
configuration of Round~0 was unaffected; its classifier re-routed 8 of
100 questions.) With a 4{,}096-token budget, 114 of the 500 questions
(22.8\%) changed route relative to the July~15 run (48
fallback$\to$R4, 27 R3$\to$R5, 14 R6$\to$R4, 12 fallback$\to$R5, 7
R6$\to$R5, 6 R4$\to$R5; 7 of them among the original 100). Yet
graph-configuration retrieval was essentially unchanged (verse
recall@5 $0.751\to0.749$, anchor coverage@5 $0.785\to0.781$). The
Ollama server that hosts the generator and the judges was upgraded
alongside this fix.

 (iii)~Judges
receive the generator's exact
context blocks, faithfulness is scored by the repaired zh and strict
judges, and verse-level retrieval metrics are computed for every run
(Section~\ref{sec:evalmetrics}). (iv)~Merged verse labels (``29--30'')
no longer break exact-verse lookup.

Two operational facts qualify the comparison. The classifier samples at
temperature 0.1, so 12 of the 500 questions (2.4\%) were routed
differently in the graph and no-graph runs although routing does not
depend on \code{use\_graph}. And one graph-run question
(VERSE\_LOOKUP\_035) lost its only strategy to a network timeout; the
archived aggregates score it as a miss (RAGAS skips it, $n=499$), while
all paired comparisons below exclude it.

Tables~\ref{tab:round3} and~\ref{tab:round3paired} support three
findings.

\textbf{The head result replicates.} On the original 100 questions the
graph configuration reads hit rate 0.97 and a $+0.16$ margin over
semantic-only (0.81) --- the Round~2 headline, reproduced by an
independent full run twelve weeks later and with a functioning
classifier. The misses changed composition: GENERAL\_008 now hits
(re-routed to R5, whose newly active entity traversal reaches
Matthew~21), EVENT\_020 now misses (Section~\ref{sec:round3mech}), and
GENERAL\_006 and PERSON\_004 still miss.

\textbf{Routing, not the graph, carries the margin.} The no-graph
configuration --- routing, SQL, and book anchors without a single Neo4j
call --- reaches 0.94 on the original 100: $+0.130$ of the $+0.160$
(95\% CI $[+0.070, +0.200]$), leaving the graph $+0.030$
($[-0.020, +0.080]$). All 13 questions that no-graph recovers come from
the 45 original questions routed R1 or R2, which cite a reference
(exact-verse lookup $+5$, chapter fetch $+8$); on the other routes
no-graph and semantic-only tie on hit rate. The graph's net share comes from EVENT questions
(0.95 vs.\ 0.80): four head events whose dictionary keywords map onto
graph event nodes (EVENT\_008/011/014/019; three of them are among the
four Round~2 flips) against one loss (EVENT\_020); elsewhere one gain
(GENERAL\_008) offsets one loss (PERSON\_004). Over all paired questions
(499), no-graph beats semantic-only on every retrieval metric (hit rate
$+0.050$ $[+0.030, +0.070]$, verse recall@5 $+0.040$, anchor
coverage@5 $+0.043$) and on answer coverage ($+0.031$ $[+0.012, +0.051]$), whereas
graph and no-graph tie on hit rate (0.944 each; seven flips each way,
one of them the infrastructure failure).
On the expansion questions the routing gain shrinks but survives (hit
rate $+0.030$ $[+0.013, +0.050]$, anchor coverage@5 $+0.024$), largely
because semantic-only itself does far better there (hit rate 0.915
vs.\ 0.810) --- many expansion questions are single-anchor long-tail
lookups that dense retrieval already finds --- and because fewer of them
cite a reference (33\% are routed R1/R2, against 45\% of the original
100).

\textbf{On questions the graph repairs never saw, no graph gain was
detected.} On the 399 expansion questions, graph minus no-graph answer
coverage is $-0.014$ $[-0.029, +0.001]$: the 95\% CI upper ends are
$+0.001$ for coverage and $+0.008$ for hit rate. Both come from one run
per configuration and resample questions only; the coverage interval is
about as wide as the $\pm 0.013$ generation-and-judge noise measured
below, so the retrieval bounds, which carry no judge noise (verse
recall@5 upper end $+0.001$), are the firmer ones. Every
retrieval point estimate is negative --- hit rate $-0.005$, verse recall
$-0.009$ $[-0.019, +0.001]$, anchor coverage@5 $-0.012$
$[-0.023, -0.003]$, MRR $-0.015$ $[-0.028, -0.002]$ --- and so is the
judged context recall ($-0.012$ $[-0.023, -0.003]$). These intervals are
per cell and uncorrected. Holm's adjustment~\cite{holm1979} over the
eight sign-flip tests of hit rate, verse recall@5, anchor coverage@5, and
MRR on all 499 and on the 399 expansion questions takes the
anchor-coverage $p$ from 0.013 to 0.107 and the MRR $p$ from 0.026 to
0.18, so no retrieval mean difference survives it; a retrieval-only
rerun of both configurations on October~3 reproduced the
anchor-coverage direction only at $p=0.060$
(Table~\ref{tab:round3paired}, notes). Only one harm statistic
survives adjustment: the graph configuration ranked
the first gold passage lower than no-graph on 35 expansion questions and
higher on 12 (MRR win:loss 12:35, sign test $p=0.001$, which survives
a Holm adjustment applied to the sign tests of the same eight cells),
and the rerun gave 13:32 ($p=0.007$).
That statistic was chosen by an audit after the Round~3 results had been seen, so this harm signal is post hoc.
Against semantic-only, the graph configuration's expansion advantage
reduces to hit rate ($+0.025$ $[+0.005, +0.048]$) and, marginally, MRR
($+0.030$, interval lower bound $\approx 0$), both uncorrected; the
intervals for verse recall, anchor coverage, context recall, and
coverage include zero. Descriptively, the losses
concentrate in the person route: on the 55 expansion questions routed
R3 in both runs, switching the graph on lowers verse recall from 0.692
to 0.627 and coverage from 0.606 to 0.567. By family
(Table~\ref{tab:round3family}) the largest losses are title\_coref
($-0.120$ verse recall), multi\_chapter ($-0.049$), and nt\_quotes\_ot
($-0.031$); typology is the one family with a sizable gain ($+0.117$,
on $n=12$). These route and family deltas are exploratory and
descriptive: they carry no intervals and no multiplicity correction, and
they rest on small subsets.

Nothing in the ranking layer asks whether a graph anchor is right. The
cross-encoder scores surface form, and the fusion prior scores the
proposing strategy: on R3, R4, and R6 a typed-graph candidate carries
$w=0.85$--$0.9$ against $0.65$--$0.7$ for a semantic one, so under
\fusedeq with $\alpha=0.3$ (Section~\ref{sec:fusionlayer}) it outranks a
semantic candidate unless the latter's reranker score is higher by
roughly 0.06--0.11. When the anchor is right --- the curated head events
--- injection plus prior is the intended rescue; when it is wrong, the
same machinery lets it through. Table~\ref{tab:round3slots} sorts the
253 questions that took the same route among R3--R6 in both runs by how
many of the five context slots graph strategies hold in the graph run.
Where they hold three, the graph run gains on the no-graph run
($+0.116$ hit rate: 5 net hits of 43, three of them on the original
100). Where they hold all five, it loses ($-0.103$ hit rate, 3 net of
29; $-0.099$ verse recall; $-0.112$ coverage), more on the expansion
questions ($-0.133$, $-0.130$, $-0.182$) than on the original 100
($-0.071$, $-0.066$, $-0.038$). The buckets are defined by the graph
run's own output, so this is a descriptive decomposition, not a
dose--response estimate.

Which part of the ranking layer lets the wrong anchors through? A
passage receives the same reranker score in both runs, so its reranker
score can be solved from its fused score and prior. On the 30
same-route questions where the graph run lost a hit or verse recall,
the reranker alone already prefers every graph-held passage to every
passage it displaced in 16 to 21 cases (depending on the exact prior of
a few strategies): the damage is done by \emph{injection} --- graph
strategies propose off-target pericopes that the surface-form reranker
then favors. In 9 cases the prior is decisive for at least one
displacement.

Three traces show both shapes. EVENT\_020 (``What story does the parable
of the prodigal son tell?'') is sent to R4 by the repaired classifier,
and \code{graph\_event} injects two \emph{other} parables --- the wicked
tenants (Luke~20, Matthew~21, Mark~12) and the sower (Luke~8) --- which
fill all five slots at fused scores 0.48--0.57. The correctly titled
Luke~15 pericope scores 0.38 in the no-graph run, and the reranker alone
already ranks the intruders higher (0.32--0.44 against 0.24; the prior
adds only 0.045). Under the silent classifier of Round~2 the same
question had fallen back to semantic search and hit. GENERAL\_048 (``love
your neighbor as yourself'': Leviticus~19, Matthew~22, Romans~13) is the
same injection case: R5's entity traversal, newly fed by the classifier,
injects Pauline Acts pericopes that out-score Romans~13 on the reranker
alone. PERSON\_066 (Timothy's grandmother and mother, 2~Timothy~1) is the
prior case: the weakest of the Acts pericopes that \code{graph\_person}
proposes for Timothy (Acts~20) and the gold 2~Timothy~1 pericope have
nearly equal reranker scores (0.073 vs.\ 0.077), and the prior
decides. The two shapes have different
roots. In EVENT\_020 the event lookup lands on the wrong entities, an
alias and entity-resolution gap of the kind the audit measured
(Table~\ref{tab:gaps}). In the other two the entity is right, but its
anchors --- the pericopes that mention it --- answer a different
question: a gap in anchor precision that the audit did not list.

Head questions are not immune. PERSON\_004, the graph's other head loss,
is a prior case: \code{graph\_person} fills all five slots with
genealogies and rosters (1~Chronicles~6, 23, 24; Numbers~2, 26),
displacing the two Exodus pericopes (the genealogy of Moses and Aaron,
Exodus~6--7) that the no-graph run retrieves; and EVENT\_020 is itself a
head question. On the original 100, however, the graph's verse-recall
losses (9 questions) are outweighed by its wins (17, all on PERSON and
EVENT questions except GENERAL\_008), whereas on the expansion set the
losses outnumber the wins 22 to 13. Among the families, title\_coref
shows the largest loss ($-0.120$ verse recall, $n=12$) and
disambiguation none.

\subsection{Faithfulness and the Measured Noise Floor}

\textbf{Faithfulness is flat at $\approx 0.98$.} Under the repaired
judges, faithfulness is 0.980--0.981 (zh) and 0.979--0.980 (strict) in
all three configurations; every configuration passes the gate (strict
$\ge 0.97$ per run, $\ge 0.95$ per type), and no paired contrast differs
from zero (Table~\ref{tab:round3paired}). The Round~0 reading that
retrieval quality propagates into faithfulness ($0.90\to0.95$,
Section~\ref{sec:round0}) is therefore not confirmed under the repaired
judge: across all paired questions the no-graph minus semantic-only
contrast is $+0.001$ $[-0.008, +0.010]$; on the original 100 a $+0.022$
tendency remains, and its interval $[-0.001, +0.052]$ just includes
zero --- and cannot exclude a gap of the Round~0 size. With citation
headers visible, the generator is about equally faithful to whatever
context it receives, and retrieval quality surfaces in coverage instead
(original 100: 0.636 semantic-only, 0.735 no-graph, 0.729 graph).

\textbf{The noise floor, measured.} Retrieval on R1, R2, and the
fallback never touches Neo4j, so 296 questions received byte-identical
contexts in the graph and no-graph runs (all 177 R1/R2 questions, 59 on
the fallback, and 60 graph-route questions whose top-5 the graph left
unchanged). Their answer-side differences are pure generation-sampling
and judge noise: answer coverage moves by a mean $|\Delta|$ of 0.060
(14\% of the questions by $\ge 0.2$; mean $\Delta=-0.002$), answer
correctness by 0.074, faithfulness by 0.028, and context recall ---
judged on the context alone --- by 0.003. With a standard deviation
of 0.131 for the per-question coverage difference, a paired difference
of two 400-question coverage means carries about $\pm 0.013$ of pure
noise at 95\% confidence --- the size of the graph $-$ no-graph
coverage difference above (the retrieval metrics carry no judge
noise), which is why every
contrast is reported paired and with an interval. The zero-slot row of Table~\ref{tab:round3slots} shows the
same floor directly: identical retrieval metrics, $+0.034$ coverage.

\subsection{What Round 3 Changes}

Four revisions to the reading of Rounds~0--2 follow. First, the
$+0.16$ head margin is real, but about four-fifths of it belongs to
signal routing --- all 13 original questions that no-graph recovers from
semantic-only come from exact-verse (R1) and chapter (R2) lookup ---
and the remaining $+0.03$ is not distinguishable from zero (95\% CI
upper bound $+0.08$). Second, the
graph's point estimate on the original 100 comes from head events whose graph
anchors were built or verified on the evaluation questions themselves;
it does not transfer to the 399 evaluable questions written afterwards, where no gain
is detected (answer coverage upper bound $+0.001$) and the graph more
often lowers than raises the rank of the first gold passage. Third,
the bottleneck
has moved: Rounds~1--2 found a ranking layer that could not
\emph{transmit} graph signal; Round~3 finds one that cannot
\emph{discriminate} it --- neither the reranker nor a fixed strategy
prior carries per-query evidence of anchor precision. Fourth, the
long-tail families --- the questions that Section~\ref{sec:p0} argued
the head benchmark could not read --- show no graph benefit either:
identical hit rates for longtail\_person, longtail\_event, and
longtail\_chapter, and verse recall $-0.027$, $+0.002$, and $0.000$,
because dense retrieval already resolves single-anchor long-tail
questions. Head saturation explains why P0 read zero on the original
100, but in this architecture a long-tail benchmark does not reveal
hidden P0 value either.

At the time, the natural next repairs were anchor-confidence gating
(admitting or weighting graph candidates by entity-resolution
confidence, with penalties for hub entities and generic events),
per-strategy slot quotas, query decomposition for multi-anchor
questions, and a re-sweep on the 500 of the $\alpha=0.3$ of
Section~\ref{sec:ablation}, which had been chosen on the original 100.
The legacy graph was retired in October 2026, and
Section~\ref{sec:rebuiltgraph} reports graph retrieval on the rebuilt
system (question sets in Section~\ref{sec:rebuiltsetup}). The rebuilt knowledge layer has no
identity or relation layer, so there is no entity-resolution confidence to gate on, and its
ranked pool holds no graph candidates (a curated event lookup lane
appends at most one passage after the top-$k$), so slot quotas and an
$\alpha=0$ run can no longer apportion graph damage. Where graph signals
could still act, no gain was detected against $k$-aligned non-graph
controls; the one positive reading, on the development set on which the
configuration was selected, did not hold on a second set. Fusing PPR or name-layer ranks into passage
selection lowered the number of missing hops recovered in a per-hop
probe on the multi-hop set OLD31 (19 and 14 of 58, against 21 for the reranker
alone; descriptive). Query decomposition, which is not a graph
operation, gained $+0.101$ in hop coverage over a deeper dense pool on
the seen multi-hop development set NEW82 (exploratory) but missed its
pre-registered bar on the 204 multi-anchor questions of the benchmark as
evaluated on the rebuilt system (GT~v2; $+0.0174$ $[-0.0025, +0.0380]$
in anchor coverage@6). Giving the decomposer
PPR-ranked names instead of non-graph names changed hop coverage on NEW82 by $-0.017$ (upper bound $+0.023$).
Both lines were stopped by the pre-registered rule; this is not
evidence of absence (Section~\ref{sec:rebuiltclosure}).
